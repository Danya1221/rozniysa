# rozniysa — розничный прайс и каталог Telegram

Витрина на основе [reprice1](https://github.com/Danya1221/reprice1), с отдельным
состоянием и собственным ботом. Исходный reprice1 продолжает работать независимо.
Оформление и заявки находятся во втором проекте: [zayavki](https://github.com/Danya1221/zayavki).

## Как работает

1. Пользовательский Telegram-аккаунт читает поставщиков: ботов с кнопками или каналы/ленты.
   Текстовые прайсы, TXT, CSV, XLSX поддерживаются унаследованным сборщиком reprice1.
2. Распознанные товары объединяются по полному варианту; среди совпадающих вариантов
   выбирается меньшая закупочная цена. Наценка задаётся суммой и/или процентом.
3. В группе/канале появляются **два сообщения меню брендов**, обложки брендов с кнопками
   разделов в две колонки и сообщения с позициями. Первое меню закрепляется.
4. Apple ведёт в iPhone по поколениям, Watch, MacBook/iMac, iPad, AirPods и аксессуары.
   Samsung — в серии смартфонов, планшеты, часы, наушники. Остальные бренды добавляются
   автоматически по распознанным позициям. Redmi/Xiaomi, Oura и DJI разделены.
5. Каждая строка товара — ссылка в обычный бот оформления. В неё передаётся стабильный
   ID позиции; цена и наличие читаются из базы бота оформления после передачи каталога по API. Изменение цены не меняет ссылку.
6. Цена в опубликованном сообщении обновляется редактированием. Лишние страницы убираются;
   навигация и закреплённое приветствие сохраняются. Кнопки между частями длинного прайса
   и возврат к бренду/общему каталогу формируются автоматически.

По умолчанию разрешены все категории и аксессуары. Неизвестные, но распознанные товарные
строки с ценой остаются в «Товары»; неподдержанный формат не угадывается. `/rejected`
показывает строки для разбора, `/status` — количество товаров и ошибок источников.
При изменении формата поставщика сверяй эти показатели с исходным прайсом.

SIM + eSIM отделена от чистой eSIM; тип не угадывается по флагу. Неизвестная SIM и
«оригинальная упаковка» скрываются. По согласованному правилу отсутствие пометки
«Актив» отображается как «Не активированное» — это правило вывода, а не проверка устройства.
Заголовки без декоративных тире. MacBook и iMac объединены; длинные разделы автоматически
разбиваются на части из-за лимита Telegram.

## Подключение: два проекта, у каждого своя база

Нужны два разных Telegram-бота и собственная постоянная база у каждого проекта.
`rozniysa` хранит сессию поставщика, настройки и IDs сообщений; `zayavki` хранит
каталог, корзины и заявки. Между ними передаются только товары и статус прайса по HTTPS.
Пароль базы заявок витрине не нужен. Исходный `reprice1` менять не требуется.

1. Сначала разверни `zayavki` по [его инструкции](https://github.com/Danya1221/zayavki).
   Получи HTTPS-домен сервиса через Railway → Settings → Networking → Generate Domain.
2. Разверни этот репозиторий отдельным сервисом Railway из ветки `main`.
   Dockerfile и `railway.toml` запускают `retail_main.py` через launcher. Одна реплика,
   `SETUP_MODE=false`. Публичный домен самой витрины не нужен.
3. В Variables укажи `BOT_TOKEN`, `ADMIN_IDS`, `API_ID`, `API_HASH`,
   `DATABASE_URL`, `ORDER_BOT_USERNAME`, `CATALOG_API_URL`, `SYNC_API_KEY` и поставщиков.
   Пример всех настроек — `.env.example`.
4. `DATABASE_URL` — база **этого проекта rozniysa**. Если здесь она называется
   `Postgres`, используй `DATABASE_URL=${{Postgres.DATABASE_URL}}`.
   В другом проекте такая же запись ссылается на его собственную базу, не на эту.
5. `CATALOG_API_URL=https://ДОМЕН-СЕРВИСА-ZAYAVKI`: только HTTPS-домен, без `/api` или `/health`.
   `SYNC_API_KEY` — один и тот же случайный секрет 32–128 латинских букв, цифр, `_` или `-`
   в обоих проектах. `ORDER_BOT_USERNAME` — username бота оформления без `@`.
6. Добавь бота витрины администратором канала/супергруппы с правами публикации,
   редактирования, удаления и закрепления. Укажи `TARGET_CHANNEL` (`@username` или `-100…`)
   либо привяжи группу через `/bind` от администратора. Нужна супергруппа или канал.
7. В личном чате с ботом витрины открой `/start` → «Telegram-аккаунты» → вход в аккаунт 1.
   Введи телефон, код и 2FA по подсказкам. Сессия сохранится в базе после входа.
   Копировать `SESSION_STRING` из рабочего `reprice1` не нужно: создай отдельную сессию.
8. Аккаунт чтения должен видеть поставщиков и состоять в закрытой группе прайса:
   это нужно для проверки отправленных сообщений после сетевого сбоя.
9. Нажми «Запросить сейчас». Проверь `/status`, `/rejected`, переход в оформление и
   контрольный заказ. При успешной передаче `/status` показывает «Каталог передан в оформление».

Состояние хранится в PostgreSQL под ключом `rozniysa_state_v1`. Volume не требуется.
Старый `RETAIL_DATABASE_URL` поддержан как запасное имя только при отсутствии `DATABASE_URL`.
Не переноси старый `state.json`: он содержит ссылки на сообщения прежнего прайса.
Если уже пользовался этой витриной, сохрани подключение к её базе при обновлении.

## Передача между проектами

Новый прайс публикуется только после подтверждения приёма полного каталога ботом
оформления. Если `zayavki` недоступен или ключ не совпадает, текущий публичный прайс
сохраняется, ошибка видна в `/status`; повтор — при следующем обновлении или запросе вручную.
Управление витриной и вход к поставщику остаются доступны.

Снимки пронумерованы; повтор запроса безопасен, запоздавшие снимки отклоняются.
Свежесть считается по времени ответа поставщика. Данные заказов/клиентов не передаются
обратно и не доступны через API. Доступ к базе другого проекта не нужен.
Ссылка на опубликованный каталог передаётся автоматически, а при сбое — с очередным снимком.

## Поставщики и настройки

| Переменная | Значение |
| --- | --- |
| `SUPPLIER_BOT`, `SUPPLIER_BOT_2` | До двух источников: username, ссылка или ID |
| `SOURCE_MODE`, `SOURCE_MODE_2` | `bot` — запросы и кнопки; `feed` — только чтение ленты |
| `REQUEST_TEXT`, `REQUEST_TEXT_2` | Например `/prices` или `/start` |
| `BUTTON_PATH`, `BUTTON_PATH_2` | Цепочка кнопок через `>`, если нужна |
| `POLL_SECONDS` | Интервал чтения, по умолчанию 600 секунд |
| `MARKUP`, `MARKUP_PERCENT` | Сумма + процент, первоначально 0 |
| `SEND_DELAY` | Пауза между изменениями сообщений, по умолчанию 1 секунда |
| `RESPONSE_TIMEOUT`, `PRICE_SETTLE_SECONDS` | Ожидание ответа поставщика / тишины после последней части |
| `MAX_CATALOG_PAGES` | Лимит обхода, по умолчанию 200; неполный обход считается ошибкой |
| `FEED_HISTORY_LIMIT` | `0` — вся доступная история ленты |
| `TIMEZONE`, `OPEN_HOUR`, `CLOSE_HOUR` | Часы подтверждения наличия, по умолчанию Москва, 10–20 |

Меню: запуск/пауза, запрос сейчас, наценка, интервал, категории, SIM-фильтр, порядок
разделов, приветствие, обложки. «Показывать все позиции» снимает сохранённые ограничения.
Порядок меняется через выбор раздела и отправку номера места; Telegram-слоты цен
переиспользуются и ссылки навигации пересчитываются. Новые фотообложки брендов могут
появляться ниже прежних постов; путь через меню остаётся правильным.

В «Обложки брендов» выбери бренд и отправь фото. По умолчанию бот создаёт нейтральные
графические обложки; свои фотографии можно загрузить без изменений кода.
Аккаунт 2 необязателен: сравнивает цену первого поставщика для второго аккаунта,
остальные источники повторно не запрашивает.

Временный тестовый iPhone и кнопка «Тест заказа» удалены. При следующей успешной
синхронизации его ссылка становится недоступной для новых заказов, а управляемый
тестовый пост убирается. Старые отдельные тестовые посты этого бота очищаются при
доступе аккаунта чтения к истории группы; остальные сообщения не затрагиваются.
Оформленные ранее заявки сохраняются. Счётчик показывает только реальные позиции.
Если отдельное название не помещается в сообщение, подпись ссылки сокращается с
многоточием; полное название остаётся в боте оформления. Остальные товары выгружаются.

## Ночь, ошибки и старые сообщения

- Заявки принимаются круглосуточно. Вне настроенных рабочих часов, при закрытии,
  ошибке или устаревшем прайсе наличие/цену подтверждает менеджер.
- Последний прайс сохраняется при сбое или закрытии поставщика. Эти цены ориентировочные:
  бот не выдаёт их за подтверждённый остаток и не резервирует товары у поставщика.
- Ошибка одного источника не стирает его прежние товары и не блокирует обновление другого.
  Распознанный товар, исчезнувший из успешного нового снимка, становится недоступным.
- Пока хотя бы один источник открыт (даже если его новый прайс пуст), явно закрытые
  источники не участвуют в выборе цен. При закрытии всех сохраняется неподтверждённый прайс.
- Смена группы блокируется на время публикации, чтобы части прайса не попали в разные группы.
  Обложки ждут завершения Telegram 429; после неоднозначного HTTP 5xx отправка проверяется
  по истории, без слепого повтора и дублей.
- Изменение цены/доступности очищает незавершённые корзины с этим товаром. Уже отправленные
  заявки сохраняют собственные цены, количество и характеристики.
- Неоднозначный исход отправки Telegram не повторяется вслепую: бот ищет свой пост
  в истории. Если проверить не удалось, администратор проверяет группу вручную и
  использует `/retry_publish` **только когда точно нет отправленного сообщения**.
- При удалённой странице восстанавливается страница и навигация. Чужие сообщения не меняются.
- Telegram ограничивает [удаление старых сообщений](https://core.telegram.org/bots/api#deletemessage)
  возрастом 48 часов. Если лишний старый пост удалить нельзя, его текст/подпись заменяются
  сообщением «Раздел обновлён» со ссылкой на актуальный каталог.

Не запускай две независимые витрины с одной базой витрины. Межпроцессная блокировка обеспечивает
последовательную смену deployment; потеря соединения блокировки останавливает процесс.

### Если группа привязана, но зависла проверка предыдущей отправки

Привязка относится к боту публикации. Историю читает пользовательский Telegram-аккаунт 1
из `/login 1`: добавь его в группу прайса и нажми «Запросить сейчас». После перезапуска
бот сам обновляет список диалогов, если Telegram ещё не знает группу по числовому ID.
Сетевые ошибки теперь отличаются от отсутствия доступа. Однозначные отказы Telegram
(включая исчерпанный 429) не оставляют зависшую отправку.

Для старой неопределённой отправки есть «♻️ Восстановить публикацию» и `/retry_publish`:
бот показывает фрагмент нужного сообщения. Подтверждай повтор только если этого сообщения
нет в группе. Старая кнопка не может сбросить другую отправку или работу в процессе.

## Проверки и локальный запуск

Python 3.12. Репозитории удобно разместить рядом: `retail/rozniysa` и `retail/zayavki`.
Для локальной разработки укажи разные файлы SQLite в `DATABASE_URL`, например
`sqlite:////absolute/path/price.db` и `sqlite:////absolute/path/orders.db`.
Для локального API разрешён `http://127.0.0.1:8080`; внешние адреса требуют HTTPS.
Локальный `rozniysa_state.json` сохраняй между запусками. В Railway используй постоянную PostgreSQL.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполни .env
python retail_main.py
```

```bash
python -m compileall -q .
python -m unittest discover -s tests -v
# Из rozniysa, если соседний zayavki уже скачан:
pip install -r ../zayavki/requirements.txt
python tests/integration_pair.py -v
```

Проверки охватывают парсер reprice1, SIM/статусы/бренды, отсутствие потерь строк,
навигацию, повторы, удалённые посты, сбои источников и контракт двух ботов.
Интеграция использует две отдельные базы и реальный HTTP-сервер на loopback.
База оформления — временная SQLite или отдельная `PAIR_TEST_DATABASE_URL`.
**Никогда не запускай тесты на рабочей базе.**

Базовый код: `reprice1@4abf0786da1d1434f09cd330c2981733dad8b0e1`.
Новые файлы `retail_*` отделяют розничную логику от унаследованной; production-вход —
`retail_main.py`, не старый `main.py`. Контракт HTTPS API — v1; совместимость двух проектов проверяется интеграционным тестом.
